## 5. Cycle de vie Singleton : le piège du repository partagé

### L'exercice
1. Ajoutez à votre `Container` la possibilité d'enregistrer une dépendance en **Singleton** (par exemple via une méthode `registerSingleton(Class<T> type, Supplier<T> factory)`) : quel que soit le nombre d'appels à `resolve`, c'est **toujours la même instance** qui doit être renvoyée.
2. Écrivez un test qui le prouve : deux appels à `resolve` sur un type enregistré en singleton renvoient la même référence (`assertThat(a).isSameAs(b)`).
3. Enregistrez `OrderRepository` en Singleton dans le câblage de `Main`.
4. Regardez (ou écrivez si besoin) `PizzaOrderConcurrencyTest` : plusieurs clients passent commande **en même temps**. Lancez-le et observez le temps total.

### Analyse
Ouvrez `InMemoryOrderRepository` : `save()` simule un vrai appel base de données (`Thread.sleep(100)`) et est `synchronized`, pour rester correct quand plusieurs threads y accèdent en même temps.

Résultat quand cette instance est un Singleton partagé par toutes les commandes concurrentes : chaque appel à `save()` doit attendre que le précédent relâche le verrou. Les commandes qui auraient pu s'exécuter en parallèle se retrouvent **mises en file d'attente**, une par une. Le temps total se rapproche de `nombre de commandes x 100ms` au lieu de rester proche de `100ms`.

**C'est le piège classique : "Singleton" ne veut pas dire "gratuit".** Partager une ressource qui fait de l'I/O bloquant (connexion base de données, appel réseau, accès disque...) en Singleton peut transformer une application entière en goulot d'étranglement (bottleneck) — même si le code est parfaitement correct et thread-safe. C'est un problème de *performance sous charge concurrente*, pas un bug fonctionnel.

### Critère de sortie
- Votre `Container` gère le cycle de vie Singleton, avec ses propres tests.
- Vous avez un test (`PizzaOrderConcurrencyTest` ou équivalent) qui **mesure** ce ralentissement (le temps total se rapproche de `N x latence` plutôt que de `latence` seule).
- Vous savez expliquer à voix haute, à votre binôme, pourquoi ça ralentit.
