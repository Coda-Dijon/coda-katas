## 4. Construire son conteneur IoC

### Objectif
Coder un mini-conteneur `Container`, capable au minimum de :
- **enregistrer** comment créer une instance d'un type donné ;
- **résoudre** (obtenir) une instance de ce type à la demande.

Pour l'instant, chaque résolution doit créer une **nouvelle instance** (comportement qui deviendra le cycle de vie "Transient" à l'étape 6, mais vous n'avez pas encore besoin de le nommer).

### Piste de signature
```java
public class Container {
    public <T> void register(Class<T> type, Supplier<T> factory) {
        // TODO
    }

    public <T> T resolve(Class<T> type) {
        // TODO
    }
}
```

### L'exercice
1. Implémentez `Container` en TDD : commencez par un test simple (`register` puis `resolve` renvoie bien une instance du bon type), puis enrichissez (deux appels à `resolve` sans singleton renvoient bien deux instances différentes, `resolve` sur un type non enregistré lève une erreur explicite plutôt qu'un `NullPointerException`...).
2. Utilisez votre conteneur dans `Main` : enregistrez toutes vos dépendances, puis résolvez un `PizzaOrderService` complet via `container.resolve(PizzaOrderService.class)`. Comparez avec le câblage manuel de l'étape 3.

### Point d'attention
`PizzaOrderService` lui-même a besoin d'être construit à partir de ses dépendances déjà résolues. Réfléchissez à comment votre `factory` (le `Supplier<T>` passé à `register`) peut, à l'intérieur de sa lambda, appeler `container.resolve(...)` pour obtenir les dépendances dont elle a besoin.

### Critère de sortie
- `Main` n'assemble plus rien à la main : tout passe par `container.resolve(...)`.
- `Container` a ses propres tests unitaires, indépendants du domaine de la pizzeria.
