## 1. Constat : un code difficile à tester

### Pour commencer
- Ouvrez `PizzaOrderService` et lisez son code en entier.
- Lancez `Main` (depuis votre IDE, ou `mvn compile exec:java` si vous configurez le plugin) : observez le temps total affiché pour 6 commandes "simultanées". On y reviendra dans les étapes 5 à 7.
- Lancez les tests existants (`mvn test`) : ils passent. Regardez surtout ce qu'ils **ne testent pas**.

### L'exercice
Essayez d'écrire, sans encore modifier `PizzaOrderService`, un test qui vérifie que :
- le `Logger` reçoit bien un message contenant `"Placing order for luke"` ;
- la `NotificationSender` envoie bien une notification au bon client ;
- le `PaymentGateway` est bien appelé avec le montant total de la commande.

Vous allez buter sur le même problème à chaque fois : `PizzaOrderService` construit lui-même toutes ses dépendances (`new ConsoleLogger()`, `new FakePaymentGateway()`, ...). Il n'y a aucun point d'insertion ("seam") pour y substituer un test double (spy, mock, fake).

### Objectif de cette étape
En pair/mob, listez à l'oral (ou par écrit) :
- tous les endroits où `PizzaOrderService` fait un `new` vers une de ses dépendances ;
- pour chacun, ce que cela vous empêche concrètement de tester ou de faire évoluer.

Pas de code à produire à cette étape : c'est un diagnostic, la base de l'étape 2.
